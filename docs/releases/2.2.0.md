# µWebZockets 2.2.0

Release date: 2026-11-10.

2.2.0 closes the response-streaming and static-asset gaps carried from 2.1.x.
Large files now leave the fixed user buffer on TLS, HTTP/2, and HTTP/3; static
mounts can select fresh precompressed representations; and the HTTP/2 output
path retains blocked stream resets without closing healthy siblings. The
release also ships the pure request-body and incremental-multipart contracts
that 2.3.0 will bind to live request transports.

## Added

- Bounded known-length file responses through `Response.stream_file` and
  `FileSource` on HTTP/1, TLS HTTP/1, HTTP/2, and HTTP/3. The transport owns
  the descriptor after acceptance and closes it exactly once on completion,
  reset, or failure.
- Static sidecar selection with `.gz` and `.br` representations, `Vary`,
  `Content-Encoding`, representation-specific validators, freshness checks,
  and encoded-range semantics. Enable with
  `App.static(prefix, root, .{ .precompressed = true })`.
- Pure content-coding negotiation over every `Accept-Encoding` field with
  explicit refusal, wildcard weights, duplicate handling, and no allocation.
- An incremental RFC 7578 multipart parser with caller-owned working storage,
  bounded carry, explicit payload acknowledgement, strict metadata, and a
  part-sink adapter with pause, resume, and once-only cancellation.
- A metadata-only `StreamingRequest`, the `BodySink`/`BodyRoute` contract, the
  `BodyState` lifecycle, and the pure HTTP/1 head/body decoder. These are the
  request-streaming foundation; live transport activation is deferred to
  2.3.0 as recorded below.
- A bounded HTTP/2 reset FIFO so an output-blocked reset no longer closes
  healthy sibling streams.
- A Woff2 MIME mapping for static assets.

## Changed

- `Response.begin_stream`, `begin_chunked`, `begin_json`, and `sse` now refuse
  to start a streaming response before the request body is complete. Buffered
  handlers remain source-compatible because the default is complete.
- HTTP/2 `send_frame` flushes retained resets before new HEADERS or DATA, and
  pending resets are bounded by the configured stream capacity.
- The timing wheel scans every overflow entry for the earliest migration time,
  so one large clock advance cannot skip an earlier due timer behind a later
  list head.
- The rate-limit bucket table, index, and LRU moved to
  `src/http/rate_limit.zig`; `middleware` keeps the public names as re-exports.
- The Nix development shell fetches the pinned zon2nix compiler from the
  maintainer's GitHub mirror while preserving the exact commit and NAR hash.

## Fixed

- Response producers that return `.done` without successfully calling
  `end_chunks` now fail closed. HTTP/2 resets only the affected stream; HTTP/3
  returns 500 before headers or closes an already-started stream. A producer
  that finishes the response is disarmed even if it later returns `.pending`.
- HTTP/2 retains reset frames during output backpressure instead of closing
  the connection.
- Large static assets no longer return 413 on TLS, HTTP/2, or HTTP/3 when they
  exceed the route scratch buffer.
- `App.static` uses the Zig 0.16 `trimEnd` API.

## Limits and dated restoration criteria

These are deliberate 2.2.0 boundaries, not hidden defects.

- **Live request-body streaming (M2-1).** The public contract, pure decoder,
  body state machine, and multipart sink are shipped and tested. No live
  transport calls the sink yet, so `Request.body` remains buffered. Restore in
  2.3.0 by binding the existing state machine to HTTP/1/TLS, HTTP/2, and
  HTTP/3, including admission, `Expect: 100-continue`, pause/resume, trailers,
  and a 100 MB bounded-memory proof on each claimed transport.
- **WebTransport (M4).** The wire helpers remain available, but the live
  listener still returns 501 for extended CONNECT and advertises no
  WebTransport settings. The maintained lsquic fork must publish the required
  server APIs and a compatible client gate before the capability bits flip.
  Reassess with the next authorized maintained-fork review.
- **Quiet-host performance evidence (M6-1).** The v2.0/v2.1 RPS, WebSocket,
  `json-comp`, and latency targets remain unclaimed on a shared runner. Restore
  on a named quiet host with the full evidence contract before publishing any
  number.
- **Receive-side UDP GRO (M6-2).** The loop still reads one datagram at a time.
  Restore when ancillary control messages expose `UDP_GRO` segment sizes and
  the pinned HTTP/3 gates pass.
- **HttpArena `async` adapter (M6-3).** The external adapter change and official
  run are outside this repository. Restore through the adapter owner.
- **Cluster runtime and timer/limiter ownership (M5).** The rate-limit table,
  index, and LRU moved to `src/http/rate_limit.zig` with unchanged
  `middleware` re-exports. The nested cluster runtime and connection parking
  state remain on the 2.3.0 structural track. Public behavior is unchanged.
- **Fork archives and second-machine resolution (M6-6).** The current pins are
  full maintained-fork commits and pass the local provenance checks. The
  optional exact-mirror run reports that upstream lsquic advanced, and the
  pinned h1spec tree still has no license notice. Final archives, mirror sync,
  second-machine resolution, and the native Windows runtime job remain
  release-owner actions.
- **kTLS and `io_uring_prep_splice` (S-3).** kTLS remains a standalone helper
  owned by v3.5.0 SB-31. Splice remains conditional on measured benefit; the
  plaintext `sendfile` path is unchanged.
